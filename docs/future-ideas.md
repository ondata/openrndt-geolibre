# Future ideas

- **A CORS proxy of our own for the web version** (2026-10-03). In GeoLibre web many services of the catalogue cannot be read for lack of CORS headers. GeoLibre's own proxy (a Cloudflare Worker) only reaches an allow-list of addresses and is "never an open proxy", so it cannot serve the hundreds of hosts RNDT links to. A Worker of ours could: CORS is a browser rule, a server-to-server request needs nothing from the publishers. To decide before building: how to keep it from being an open proxy (GET only, only requests shaped as WMS, WFS or ArcGIS REST, only from `web.geolibre.app`, a ceiling on requests); cost (one request per map tile, 100,000 a day on the free plan); that the users' traffic passes through it, so opt-in and said in the panel; that layers added through it are saved in the project with the proxy's address, which Desktop does not need. Publishers that block by IP or country stay out of reach.
- **RNDT among GeoLibre's built-in "Web Services"** (2026-10-03). That submenu groups the built-in catalogue browsers; it is a fixed list of plugin ids, so a registry plugin cannot join it. As a built-in the plugin would get `?plugin=`, no trust prompt and the host's proj4. It would be the first browser of an ISO/INSPIRE metadata catalogue there (the list has STAC, CKAN, Socrata, ArcGIS). To ask the maintainer first: whether a national Italian catalogue is welcome as a built-in, or a field to put a registry plugin in that submenu.
- **Precise datum conversion with IGM Verto Online** (Desktop only). GeoJSON files in Roma40 (EPSG:3003/3004/4265) and ED50 (4230, 23032/23033) are converted with proj4's 7-parameter shifts, which are off by about a metre, sometimes a few, since the Italian datum deformation is not uniform. The official IGM grids are centimetre-precise and reachable through the Verto Online API (`POST` JSON to `https://igmi.esercito.difesa.it/porta-magna/wps/volapi`, the service behind [openverto](https://github.com/ondata/openverto)). As an explicit plugin setting, off by default: each conversion is a network call that sends the dataset's coordinates to an external service, and openverto chunks requests at 32,000 points. To check first: terms of use, rate limits, and whether the server sends CORS headers (the web version needs them; Desktop's native client does not). Python is not an option: GeoLibre Desktop gives plugins no interpreter and no command execution. (2026-10-02)
- **Empty pictures from a WMS**: the test tile checks that an image of the asked size comes back, not that it shows anything. ISPRA's "Abruzzo topografia 25k" answers every GetMap with the same all-black PNG (its ImageServer is a 1-bit raster of zeros, 2026-10-02) and the panel adds it as if it worked. Telling "empty because broken" from "empty because nothing is there" would take a second request on the layer's whole extent.
- **Service records without an endpoint**: a record of type service that lists only web pages (the Marche WebGis, the Ministry's ortofoto UTM33 record) shows "Other links" alone. A line saying "this service record declares no WMS, WFS or ArcGIS REST endpoint" would say why there is nothing to add.
- **CORS message**: "no CORS header in its answer" also covers a server that sends two `Access-Control-Allow-Origin` headers (ISPRA's ArcGIS, 2026-10-02), which browsers reject as well; "no CORS header, or more than one" would be exact.
